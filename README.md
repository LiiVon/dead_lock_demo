# 简易 C++ 死锁检测组件 
## 一、组件简介
一款轻量、无第三方依赖、纯用户态的 C++ 死锁检测小组件，基于资源分配图 + DFS 环路检测实现，专门用于检测经典的AB-BA 锁顺序反转死锁。
适用于：学习原理、项目调试、面试手写死锁检测器场景。
运行平台：Linux
## 二、功能特性
- ✅ 封装原生 std::mutex，零业务侵入，只需替换锁对象即可开启检测
- ✅ 基于操作系统资源分配二部图理论，精准判断死锁环路
- ✅ 加锁前置预判，不会卡死线程，检测到死锁直接告警并断言退出
- ✅ 全局单例检测器，多线程安全，自带锁保护数据结构
- ✅ 自动为每一把锁分配唯一 ID，精准定位死锁锁资源
## 三、核心实现原理
1. 资源分配图模型
维护两张核心映射表，构建线程与锁的依赖关系：
- 持有关系：lock_id ➝ 持有该锁的线程TID
- 等待关系：TID ➝ 当前线程正在阻塞等待的锁集合
2. 死锁判定逻辑
线程加锁前，通过 DFS 深度优先遍历 遍历资源依赖图：
如果遍历出现闭环环路 = 存在死锁依赖 ➝ 预判死锁并告警
3. 加锁完整埋点流程
1. 线程尝试加锁，前置调用死锁检测函数
2. 若检测到环路，打印死锁告警 + 断言崩溃
3. 若无死锁，记录「线程正在等待该锁」
4. 调用原生 mutex 阻塞加锁
5. 加锁成功：清除等待记录，新增锁持有记录
6. 解锁时：清除锁持有记录
## 四、编译与运行
编译命令
g++ main.cpp -o main -std=c++11 -pthread -g
运行
./main
正常触发死锁输出

## 五、项目集成使用方式
零侵入改造：业务代码中，将所有 std::mutex 直接替换为 SafeMutex 即可开启死锁检测。
示例：
// 原代码
// std::mutex m1, m2;

// 改造后（自动开启死锁检测）
SafeMutex m1;
SafeMutex m2;
## 六、测试用例说明
内置经典 AB-BA 死锁场景：
- 线程A：先锁 m1，再锁 m2
- 线程B：先锁 m2，再锁 m1
锁顺序反转形成依赖环，组件可提前预判捕获，避免程序永久卡死。
## 七、组件局限性
该组件为学习调试版 Demo，存在明确局限
- 1. 仅监控自定义 SafeMutex，原生 std::mutex / pthread_mutex 无法检测
- 2. 不支持递归锁、条件变量 condition_variable 引发的死锁
- 3. 仅能检测 锁顺序反转(AB-BA) 死锁，无法检测资源耗尽、业务逻辑死锁
- 4. try_lock 接口未做死锁检测逻辑
- 5. 全局检测器单例加锁，高并发下存在轻微性能损耗
## 八、工业级替代方案（生产推荐）
开发/生产环境不使用自研Demo，推荐编译器原生检测工具：
# ThreadSanitizer 一键检测死锁、数据竞争
g++ main.cpp -o main -fsanitize=thread -g -pthread
